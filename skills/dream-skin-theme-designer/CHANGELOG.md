- Color changes must have a perceptible purpose: if the wallpaper or palette doesn't offer a genuinely better alternative for a given key (e.g. `text` is already a good near-white), leave it unchanged. Do not swap one near-white for another near-white just to fill a diff.
- Sub-threshold brightness tweaks (individual hex channels differing by single digits) are invisible to the human eye — don't write them. Either make a change that crosses a perceptual threshold (different hue, meaningfully different lightness step) or make no change at all.
- Modifying an existing theme must now touch **every** color key relevant to the requested tone shift (text/muted included), not just accent colors — a "brighten this theme" request that leaves `text`/`muted` untouched under-delivers even if contrast still passes.
- When modifying a theme, present a before/after table of every changed hex value so the user can see the actual delta, not just a claim that colors were "improved."
